# Protocol Conformance Matrix

This matrix keeps the executable checks grouped by protocol layer.

| Layer | Cases |
|---|---|
| Handshake | valid v1, capabilities recorded, malformed hello, malformed capabilities, `registries` (absolute http(s) URLs, unique, may be empty), no compatible version, fallback-enabled version mismatch, close-before-ready |
| Request schema | unknown request kind, removed kinds (`get-batch`, `refresh`) well-formed and left to the provider, as any unknown kind, missing registry, missing operation, missing interactive, every npm action a known operation, `access`, `trust` and `account` included, which cover reads, coarse or unknown operation rejected, `publish`, `stage` and `stage-reject` without version, `retry` without `httpStatus`, invalid `httpStatus`, invalid `authChallenges`, unlisted `command` accepted, unknown fields ignored |
| Response schema | exactly one of `Ok`/`Err`, required `Ok.kind`, invalid `Ok`, `Ok` for a removed kind, invalid `Err`, bearer/basic auth validation, unknown auth type, invalid cache, missing `expiresAt`, invalid granularity, invalid `operationIndependent`, unknown fields ignored |
| JSON Schema | schema artifact is valid draft 2020-12 JSON Schema, generated positive and negative protocol vectors validate when `jsonschema` is installed |
| Spec consistency | schema enums, operations that require `version`, hello capabilities, policy values, and Python model constants stay in sync |
| Codegen | generated Python/Rust constants, policy summary, and protocol vectors are fresh relative to `spec/policy-v1.json` |
| Errors | `url-not-supported` and `not-found` move on to the next provider, `operation-not-supported` fails for every kind, `other` |
| Registry matching | trailing slash at a segment boundary, `/npm` against `/npmx`, host case, explicit default port, non-default port, path case, percent-encoding not decoded, dot segments, scheme compared only for hello entries, IDN host, lookalike hosts |
| Phase 2 rules | non-read answers bound to operation and package (workspace publish), scheme in the cache key, queued re-lookup, absent fields in the key; a request tied to the answer it carried (stale 401), erase with `version` and `granularity`, a second 401 erased without retry, a 403 retry answer replacing the refused credential, the rejection table, a 403 retry with no erase and one retry per request (transcripts); hello `registries` filtering and the listed-host warning; killed twice for a timeout; line-size floor, interactive rule, sentinel argument in policy |
| Chain rules | `login` and `logout` ending as `get` does (implicit `npm:token` only after every provider declined, with a warning; no token stored after a `not-found`), an OIDC token asking no provider and drawing no warning, npm's one-time-password classification of a 401, a `stage-read` answer never serving `publish` or `stage-reject` |
| Chain | every `fallback` key of the policy: no provider, a global chain that declines (stored credential with a warning, else anonymous), a per-registry list that declines (fails, warns about an ignored stored credential), `not-found` at the end (fails unless `npm:token` is listed), a version mismatch, other failures; `npm:token` listed or implicit; `url-not-supported` asked once per provider and registry |
| Cache | `registry`, `scope`, `package`, `cache=never`, `cache=session`, `cache=expires`, `operationIndependent` default `false` and `true`, lookup most-specific-first, operation-bound before operation-independent, a `stage` token never serves `publish`, expiry margin, no key collision between levels |
| Token helper (Phase 1) | output trimmed with JavaScript semantics (BOM included), raw token sent as `Bearer`, output matching `^[A-Za-z]+ ` used as the header, empty output and non-zero exit fail, output with a character outside tab and printable ASCII (second line, `\x7f`, non-ASCII) refused without quoting it, user/global config only, absolute POSIX or Windows path only, a spaced path accepted when it exists and otherwise refused as arguments (a prefix before whitespace is a file) or as not found |
| Resolution | project config rejected, workspace config rejected, global/user config accepted, project `node_modules` ignored, current directory ignored, PATH-like locations ignored, a name in two npm-managed global bin directories fails closed |
| Transcripts | get success, provider chain, not-found, version mismatch, erase followed by one retry with `httpStatus` |
| Subprocess | valid get, expiring token re-acquired with a plain `get`, login/logout/erase, malformed auth, invalid JSON, no hello, both `Ok`/`Err`, provider timeout |
| Rust PoC | real client/provider exchange for get and publish, fail-closed errors, malformed wire responses, provider chaining (global and per-registry exhaustion, `not-found` passing on), several sequential requests in one provider process, unknown request kind and unknown operation refused without ending the session, oversized line rejected whole, secrets redacted from `Debug` |
