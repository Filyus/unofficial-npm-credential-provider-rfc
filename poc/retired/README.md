# Retired mechanisms

A mechanism of the Phase 1a prototype that a review replaced or dropped is not deleted and forgotten. It stays here as a patch that restores it, so that bringing it back is one `git apply` and not an archaeology job, and CI proves that each patch still applies to the prototype and that the tests it restores pass.

Each patch applies on top of the npm/cli prototype: the base commit `ae98c62` with [`poc/patches/npm-cli.patch`](../patches/npm-cli.patch). It puts the old code, its documentation line and its tests back; the tests the new mechanism has in their place are changed or removed by the same patch. [`retired.json`](retired.json) is the list the workflow, [`run.js`](run.js) and [`poc/claims/check.js`](../claims/check.js) share, and the table below must name the same patches (the check fails when a patch has no row or a row has no patch).

`child-untrusted-marker` and `child-transport-marker` both add the field `#tokenHelperSeen` to `workspaces/config/lib/index.js`, so they are applied one at a time, never together. Every other patch is independent of the rest, and each is meant to be applied alone to the prototype, as `run.js` does; the four of pass 1 (`cmd-path-characters`, `stderr-control-characters`, `config-set-refusals`, `helper-exit-code-field`) were made against the final tree, so they restore the code as it stood just before each was removed.

## Restoring one

1. Build the prototype tree as the [`prototype` workflow](../../.github/workflows/prototype.yml) does: npm/cli at `ae98c62`, `node scripts/resetdeps.js`, then `git am poc/patches/npm-cli.patch`.
2. In that tree, run `git apply <this folder>/<name>.patch`. The patch changes the files and the tests; the tap files to run are in the last column and in `retired.json`.
3. To make it part of the prototype again, fold the change into the two commits of `poc/patches/npm-cli.patch` (the core one and the follow-up), regenerate the patch with `git format-patch --stdout ae98c62..token-helper`, and update the implementation document: [Rule by rule](../../phase-1a-implementation.md#rule-by-rule), [Limits](../../phase-1a-implementation.md#limits) and the line counts in [Submissions](../../phase-1a-implementation.md#submissions), which `poc/claims/check.js` compares with the patch.
4. Take its row out of the table here, its entry out of `retired.json` and the patch out of the folder in the same commit.

To try one without touching a checkout: `node poc/retired/run.js <npm/cli tree with no changes>` applies each patch in turn, runs its tests and restores the tree.

| `child-untrusted-marker.patch` | The parent npm exported `npm_config_token_helper_untrusted`, naming the user and global files it had refused, and a child npm refused them too | A repository's script that runs `npm`: a file that a project's `userconfig`, `globalconfig` or `prefix` selected can lie outside the repository, and the child saw only an environment value for it. | `child-transport-marker.patch` | The parent npm exported `npm_config_token_helper_project_transport`, naming the route keys (`proxy`, `https-proxy`, `ca`, `cafile`, `strict-ssl`) it had taken from a project, and the child counted their values in its environment as the project's | A repository's script that runs `npm`: the parent exports its resolved config to the child as `npm_config_*`, which the child reads as the user's own, so a project's proxy or CA would have lost its origin. | `helper-env-editor-node-env-color.patch` | The helper's environment lacked `EDITOR`, `NODE_ENV` and `COLOR` where npm had set them from `editor`, `omit` (or `production`, `only`) and `color`, and a child npm recognised the values its parent had set | A helper that reads one of them, and a project `.npmrc` that sets the config key behind it. | `route-proxy-over-https.patch` | A project's `proxy` or `https-proxy` refused a helper's credential for an `https:` request too, as it still does for `ca`, `cafile` and `strict-ssl=false` | A helper's credential sent through a proxy that a repository chose. | `publish-config-precheck.patch` | `publish` and `unpublish` refused a `publishConfig` route key for a registry a helper serves, before anything ran, in `lib/utils/publish-config.js` | A repository's `package.json` that sets `publishConfig.proxy`, `ca`, `cafile` or `strict-ssl` so that `npm publish` sends a helper's credential over a route the repository chose. | `cmd-path-characters.patch` | A `.cmd` or `.bat` helper path that contained `"`, `%` or `!` was refused, in `refusal()` of `lib/utils/token-helper.js`, with a comment in `command()` and a row in the documentation | cmd.exe reinterprets `%VAR%` inside quotes and a `"` ends the quoting, so a path with them could run something else than the file. | `stderr-control-characters.patch` | Control characters (C0 and C1 but tab) were stripped from each line of a helper's stderr before it was shown or logged, next to the masking of the exact token, in `shown()` | A helper that relays a registry's text could put escape sequences on the user's terminal. | `config-set-refusals.patch` | `npm config set` refused `tokenHelper` in project config and the unscoped form, in `lib/commands/config.js`, with a line in the documentation | A user who wrote a setting that npm then ignores. The load-time warning already names both cases (a project `tokenHelper` and the unscoped form are ignored with a warning that says what to write), so the refusal at `set` time only repeated it | The load-time warnings are found not to reach a user who set the value with `npm config set` | `test/lib/commands/config.js` ("config set tokenHelper": the scoped form in user config, the unscoped form and project config refused) | 122, observation 777 |
| `helper-exit-code-field.patch` | `ETOKENHELPER` carried the helper's exit status as the property `helperExitCode` (constructor option, `failure()`, asserts in the tests); `signal` stays | A caller that wants the status as data. Against nobody: no attacker is involved | Pass 1: no matrix cell worsens without it. The Decision column is the number of the decision in the project's knowledge base that retired it (for pass 1, also the observation that holds the scenario matrix).
