# Retired mechanisms

A mechanism of the Phase 1a prototype that a review replaced or dropped is not deleted and forgotten. It stays here as a patch that restores it, so that bringing it back is one `git apply` and not an archaeology job, and CI proves that each patch still applies to the prototype and that the tests it restores pass.

Each patch applies on top of the npm/cli prototype: the base commit `ae98c62` with [`poc/patches/npm-cli.patch`](../patches/npm-cli.patch). It puts the old code, its documentation line and its tests back; the tests the new mechanism has in their place are changed or removed by the same patch. [`retired.json`](retired.json) is the list the workflow, [`run.js`](run.js) and [`poc/claims/check.js`](../claims/check.js) share, and the table below must name the same patches (the check fails when a patch has no row or a row has no patch).

Each patch is independent of the rest, and each is meant to be applied alone to the prototype, as `run.js` does; the four of pass 1 (`cmd-path-characters`, `stderr-control-characters`, `config-set-refusals`, `helper-exit-code-field`) were made against the final tree, so they restore the code as it stood just before each was removed. A mechanism that a later pass found was needed is taken out of the folder when it is folded back into the prototype: `child-transport-marker` (pass 2) and `child-untrusted-marker` (pass 3) are no longer here, and the retired comparison that replaced the first is.

## Restoring one

1. Build the prototype tree as the [`prototype` workflow](../../.github/workflows/prototype.yml) does: npm/cli at `ae98c62`, `node scripts/resetdeps.js`, then `git am poc/patches/npm-cli.patch`.
2. In that tree, run `git apply <this folder>/<name>.patch`. The patch changes the files and the tests; the tap files to run are in the last column and in `retired.json`.
3. To make it part of the prototype again, fold the change into the two commits of `poc/patches/npm-cli.patch` (the core one and the follow-up), regenerate the patch with `git format-patch --stdout ae98c62..token-helper`, and update the implementation document: [Rule by rule](../../phase-1a-implementation.md#rule-by-rule), [Limits](../../phase-1a-implementation.md#limits) and the line counts in [Submissions](../../phase-1a-implementation.md#submissions), which `poc/claims/check.js` compares with the patch.
4. Take its row out of the table here, its entry out of `retired.json` and the patch out of the folder in the same commit.

To try one without touching a checkout: `node poc/retired/run.js <npm/cli tree with no changes>` applies each patch in turn, runs its tests and restores the tree.

| `cmd-path-characters.patch` | A `.cmd` or `.bat` helper path that contained `"`, `%` or `!` was refused, in `refusal()` of `lib/utils/token-helper.js`, with a comment in `command()` and a row in the documentation | cmd.exe reinterprets `%VAR%` inside quotes and a `"` ends the quoting, so a path with them could run something else than the file.
