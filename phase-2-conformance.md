# Phase 2 conformance

What the conformance material for [Phase 2](phase-2-credential-provider.md) checks, rule by rule, and what only an npm client can show. The rules are data in [`spec/policy-v1.json`](spec/policy-v1.json); the schema, a Python model of the client, a Rust client and provider pair and the reference providers in [examples](examples/README.md) are held against them.

| Artifact | What it is |
|---|---|
| [spec/protocol-v1.schema.json](spec/protocol-v1.schema.json) | JSON Schema of every message |
| [spec/policy-v1.json](spec/policy-v1.json), [summary](spec/generated-policy-summary.md) | The rules as data: timeouts, cache, fallback, chain, rejection |
| [tests/generated_protocol_vectors.json](tests/generated_protocol_vectors.json) | Valid and invalid messages generated from the policy |
| [tests/](tests) | An executable Python model of the client, with transcripts |
| [poc/rust](poc/rust) | A Rust client and mock provider pair |

Prerequisites and the commands that run all of it are in the [README](README.md#running-the-checks).

## Rule by rule

Each row is a rule of Phase 2 and what backs it, written as `kind: text`: `spec` is a key of the policy; `py` a test module in [`tests/`](tests), or `module.test_name` or `module.Class.test_name` for a test in it; `js` a test title in [`examples/providers/*.test.js`](examples/providers); `rs` a Rust test function under [`poc/rust/crates`](poc/rust/crates). [`poc/claims/check.js`](poc/claims/check.js) confirms in CI that each one still exists. A bare `py` module name proves only that the file exists, and finding a test does not show that it asserts what the row says: that is for the row's wording and for a reader of the test. Evidence given as a link to a file is not looked up.

## Differential fuzzing history

- The nightly of 2026-10-19 (run 39191203253, 4 503 000 messages) found one case in dispute: the request kind `"logi\n"`, which the Python model and the JavaScript providers refused and the schema accepted, because Python's `jsonschema` lets `$` match before a trailing newline. The readers were right, and the schema's pattern was tightened after it.
- Before that run, a run of 100 s covered 756 000 messages with none in dispute (measured once, not re-run by CI).

## What only an npm client can show

npm has no Phase 2 client, and the Rust `mock-client` is a test harness for the protocol, not an npm client. These behaviours are not verified:

- masking and control-character stripping of provider stderr and error messages;
- the `.cmd` argument quoting and refusals;
- the Windows working-directory limit for providers;
- `${VAR}` expansion of per-registry provider lists;
- who owns the provider process;
- that an interactive request goes through npm's input bracket.
